# RecoMart End-to-End Data Management Pipeline for Recommendations

This repository implements Assignment I: a modular data management pipeline for an e-commerce recommendation system. It covers problem formulation, ingestion, raw storage, validation, preparation, transformation, feature management, data versioning/lineage, model training, and orchestration.

---

## Quick Start

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m src.orchestration.pipeline
python -m src.inference --user_id U001 --top_k 5
```

The submitted ZIP already includes generated sample data, validation reports, feature-store materialization, trained model artifact, and experiment metadata.

---

## Folder Structure

- `src/ingestion`: CSV and REST API ingestion with retry logic and logging.
- `src/validation`: automated data quality checks and report generation.
- `src/preparation`: cleaning, encoding, normalization, and EDA.
- `src/features`: user, item, user-item, and co-occurrence feature transformations.
- `src/feature_store`: custom versioned feature registry and retrieval.
- `src/training`: SVD collaborative filtering model with evaluation metrics and MLflow tracking.
- `src/orchestration`: pipeline execution with DAG structure.
- `data/raw`: partitioned immutable raw data by source/type/timestamp.
- `data/prepared`, `data/transformed`, `data/feature_store`: curated datasets and feature storage.
- `models`: trained model artifacts.
- `reports`: evaluation results, EDA outputs, and metrics.
- `docs`: SQL schema, feature metadata, and lineage/versioning workflow.

## Model

The training stage builds a collaborative filtering recommender using truncated SVD over the user-item interaction matrix.

- Handles sparse interaction data effectively  
- Learns latent user and item representations  
- Generates personalized recommendations  

The model is evaluated using:
- Precision@K  
- Recall@K  
- NDCG@K  

Recommendations are generated by ranking items based on predicted relevance scores.

Artifacts are stored in:
- `models/` (trained model)
- `mlruns/<run_id>/` (experiment tracking)

## MLOps Integration

This project incorporates modern MLOps practices:

### DVC (Data Version Control)
- Tracks dataset versions and pipeline stages  
- Maintains data lineage across transformations  
- Ensures reproducibility  

### MLflow
- Logs model parameters, metrics, and artifacts  
- Tracks experiments with unique Run IDs  
- Enables comparison of multiple model runs  

To view experiment tracking:

```bash
mlflow ui --backend-store-uri ./mlruns
```
